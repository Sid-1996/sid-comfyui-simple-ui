# Civitai 個人電腦搜尋／下載體驗 — 設計導正審查

> 本報告為唯讀設計審查。依據上層與 Repo 的 AGENTS.md、既有可行性調查、階段 A/R1 報告及目前工作區實際程式碼。
> 唯一寫入為本報告；未修改程式碼、設定、使用者資料或既有報告。

## 1. 審查問題與結論

目標是讓使用者在自己的 PC 上，從 Sid-simple-ui 搜尋 Civitai LoRA、查看模型資訊，並直接下載到 ComfyUI 可用的 LoRA 目錄。

**結論：值得做。** 這能把「找模型 → 下載 → 手動找資料夾 → 放進 ComfyUI → 回到 UI」縮成同一個探索流程，直接降低非技術使用者的操作成本，也符合專案「一頁、少步驟、白話錯誤」的方向。

但應將它定位為既有 LoRA 探索中心的延伸，而不是帳號整合子系統。現階段設計有幾處可以收斂：

1. 不需要為了公開搜尋要求使用者設定 API Key。
2. 不需要先建完整 OAuth 或帳號登入架構。
3. 不需要把下載做成獨立下載管理器、佇列系統或 WebSocket 子系統。
4. 不應把階段 A 的 Key 設定介面當成獨立可交付功能；目前它尚未解鎖搜尋或下載能力。
5. 第一版不需要支援多檔案選擇、續傳、多工併發、下載歷史或任意路徑設定。

## 2. 規範與產品方向核對

### 2.1 AGENTS.md 的核心約束

- 產品面向非技術使用者，要求一屏到底、主要動作單純、錯誤訊息告訴使用者下一步。
- 前端維持原生 HTML/CSS/JS，後端維持 Python 標準庫，不新增框架、Build System 或第三方 Python 套件。
- ComfyUI API 必須經由 Sid-simple-ui 後端代理；不得讓前端直連 ComfyUI。
- 不得假設公開使用者的本機路徑；模型目錄應由 ComfyUI 實際設定取得。
- 不可擅自下載模型、安裝依賴或改動正式服務。
- 不應破壞既有探索、圖片安全判斷、localStorage 格式與一屏版面。

### 2.2 是否符合產品定位

Civitai 探索中心已存在，且目前公開搜尋不需 Key。增加「下載到本機 LoRA 目錄」是既有功能的自然下一步，不是新增另一個產品入口。

使用者真正需要的是「找到想要的 LoRA 後，按一下就能在本機使用」，不是「登入 Civitai 帳號」本身。因此 UI 應以模型搜尋與下載為主，Key 僅是下載授權的可選設定。

## 4. 建議收斂後的產品體驗

### 4.1 搜尋：永遠先維持匿名公開搜尋

- 未設定 Key：照常搜尋、排序、分頁、預覽公開模型。
- 已設定 Key：一般公開搜尋仍維持匿名，不因 Key 存在就把所有搜尋改成 Bearer。
- 第一版不做 Favorites、Hidden、個人化推薦等需要帳號身分的功能。

理由：公開搜尋已經可用；把 Key 放進一般搜尋沒有必要，反而擴大憑證使用範圍與快取隔離複雜度。

### 4.2 下載：以一次點擊完成為目標

建議第一版流程：

1. 使用者在既有 Civitai 搜尋結果找到 LoRA。
2. 點擊「下載」。
3. 後端先取得／確認版本與主要檔案 metadata。
4. 若公開下載可行，直接下載；若 Civitai 回覆需要帳號授權，才提示設定個人 API Key。
5. Key 保存並通過 /me 驗證後，重試原下載。
6. 下載到 ComfyUI 實際設定的 LoRA 目錄。
7. 驗證 SHA-256，完成後刷新既有本機 LoRA 清單，提示「已可使用」。

Key 是可選的下載授權，不是搜尋門檻，也不應把它呈現成完整登入系統。

### 4.3 Key UI：從常駐管理列降級成按需設定

建議：
- 探索彈窗只保留低干擾狀態，例如「下載授權：未設定／已設定」及設定入口。
- 未設定 Key 的使用者仍能完整使用公開搜尋。
- 只有下載確實遇到授權需求時，才明確引導設定 Key。
- 保存時可直接呼叫 /me 驗證，減少「儲存」後還要再按一次「測試連線」的流程；若保存與驗證分離，必須清楚顯示「已保存但尚未驗證」。
- 保留移除本機 Key 的能力，並提醒本機移除不等於撤銷 Civitai 端的 Key。
- Full Access、Buzz 與 DPAPI 的完整風險說明放在展開說明／文件；主畫面只保留必要、可理解的短提醒。

不建議把 Key 管理做成全站設定頁、帳號個人資料頁或 OAuth 登入流程。

## 5. 第一版下載範圍：必須有與應延後的項目

### 5.1 必須有（安全與基本可用性）

- 以 Model Version ID 作為下載識別。
- 先取得版本 metadata，明確選定檔案；首版預設只下載 primary file。
- 只寫入 ComfyUI 實際設定的 LoRA 目錄，不接受任意使用者輸入路徑。
- 檔名清理，阻擋路徑穿越、Windows 保留名稱及同名覆蓋。
- 下載寫入同目錄暫存檔（例如 .part），完成 SHA-256 驗證後原子改名。
- 失敗、取消或雜湊不符時清理暫存，不破壞已存在檔案。
- UI 顯示下載中、完成、失敗及白話錯誤；下載不能阻塞 HTTP handler。
- 下載授權只在必要的 Civitai 官方請求上使用；redirect 必須逐跳驗證，不能把 Bearer 傳給 CDN。
- 401、403、429、404 與網路錯誤要區分，不可把權限不足說成 Key 無效。
- 下載完成後刷新既有本機 LoRA 清單。
- 以本機 mock 測試 redirect、Authorization 不外洩、SHA mismatch、部分檔案清理、路徑與檔名攻擊、同名檔案保護。

### 5.2 第一版可延後（避免過度設計）

- 多檔案版本的完整檔案選擇器：先只支援 primary file，並顯示實際檔名與大小。
- Range／續傳：先整檔下載；失敗清理暫存後讓使用者重試。
- 多工併發下載、下載佇列、跨重啟任務恢復。
- WebSocket 進度推播：先用低頻率 HTTP polling。
- 下載歷史、收藏、個人化搜尋、模型更新追蹤。
- 自動建立分類目錄、任意自訂下載路徑、跨 ComfyUI 多實例管理。
- OAuth、第三方登入、Refresh Token、帳號同步。
- 新增獨立 Python Worker 程序或第三方下載套件。

首版可限制同時一個下載任務；若使用者真的同時下載多個模型，再依實際需求擴充。

## 6. 安全與技術取捨

### 6.1 Personal API Key 是否值得

對「個人 PC 自架、自用」情境，Personal API Key 是比 OAuth App 註冊更低門檻的折衷方案；但它不是一般登入憑證，也不是低權限 Token。

- 只在需要帳號授權的下載請求使用。
- Key 留在後端，DPAPI CurrentUser 加密保存；不進前端狀態、localStorage、URL、日誌或錯誤訊息。
- 主動告知 Full Access 可能涉及高權限及 Buzz 支出；鼓勵使用者選擇符合需求的最低權限 Key（實際可用 scope 必須依 Civitai 當前介面與文件確認）。
- DPAPI 是 Windows 使用者環境保護，不應宣稱可防同一使用者權限下的惡意程式。
- Civitai 官方偏好第三方 App 使用 OAuth；本專案採 Key 是為了自架低設定門檻，文件需如實說明。

### 6.2 Redirect 與下載安全不可省略，但不要預先實作完整通用下載框架

R1 已採取帶 Bearer 請求不自動跟隨 redirect 的保守策略。下載階段不能直接恢復 urllib 預設 redirect。

下載應固定從 Civitai 官方 HTTPS 端點開始，逐跳檢查 HTTPS、允許的交付 Host、跳轉次數及目的 IP；跨 Host 不傳 Authorization。CDN 網域清單與 DNS/IP 防護應在階段 B 的專項調查中，以實際官方下載流程確認後再定義，不能憑猜測放行所有外部 Host。

不要為了「通用性」做可下載任意 URL 的 API；下載入口只接受版本 ID，下載 URL 由後端向 Civitai 取得並驗證。

### 6.3 儲存目錄

下載目的地應使用 ComfyUI 的 `folder_paths.get_folder_paths("loras")` 實際設定，不硬編碼 `models/loras`，也不要求使用者手動輸入絕對路徑。

若 ComfyUI 回傳多個 LoRA 目錄，首版先採用明確的預設目錄並在完成提示中顯示實際位置；除非實際使用者驗收證明有必要，否則先不做多目錄管理 UI。

## 7. 建議實作順序

1. **階段 A（已完成程式實作，待最終安全審查）**：Key 加密保存、/me 驗證、移除與最小 UI。不要獨立宣稱已提供完整 Civitai 帳號整合。
2. **階段 B（下一個真正有產品價值的階段）**：下載最小閉環：primary file、單一任務、HTTP polling、ComfyUI LoRA 目錄、SHA-256、原子改名、失敗清理、redirect 防護、完成後刷新清單。
3. **階段 C（使用者驗收後）**：依真實使用痛點補多檔案選擇、續傳、併發或多目錄支援；沒有痛點就不做。

階段 B 開始前仍需完成階段 A R1a 的空 Port 邊界修正與獨立審查；未通過前不應讓帶 Bearer 的功能進入下載實作。

## 8. 最終設計決策建議

**採用「匿名搜尋 + 可選個人 Key + 一鍵下載到 ComfyUI LoRA 目錄」的最小整合。**

保留已完成的 Key 後端安全基礎，不恢復 OAuth；但調整 UI 呈現，讓 Key 不再像登入必要步驟。第一版下載只做 primary file、單一任務、簡單進度、SHA 驗證與安全寫入。所有更複雜能力都等使用者實際遇到限制後再做。
