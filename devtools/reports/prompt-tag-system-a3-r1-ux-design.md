## 4. Prompt／Tag／Negative 操作流程分析（A）

### 4.1 現況流程

【已驗證】開頁 → 左欄點分類／搜尋 → 點標籤進底列（可 −/＋/× 調權重、自動或手動排序）→ 在 `#pos` 打中文 → 必要時展開左欄 `<details>` 設 `#neg` → 右欄設尺寸／張數／LoRA／品質開關 → 底列按「生成」。`snapshotNow()` `322-350` 把 `QUALITY + sel(權重) + Dict.tr(#pos) + loraTokens` 組成正向字串，負向原字串直通 `wf()` node 3。

### 4.2 主要發現

| # | 發現 | 證據 | 困難 | 原因 | 建議 UX | 相容性影響 | 優先 |
|---|---|---|---|---|---|---|---|
| A1 | 品質詞有兩個入口 | 【已驗證】真實 UI 左欄「常用」前五個是品質標籤；右欄 `q` 又自動加 `masterpiece, best quality, amazing quality`。`tags.js:10`、`app.js:12`。 | 使用者不知道要不要手動點，可能重複。 | 兩個來源都進正向；目前無全域去重（A2 契約才有）。 | 合併：右欄只留一個「畫質加成」開關；左欄品質標籤移到進階或移除。 | 不改資料；只改入口。 | P0 |
| A2 | Tag 與補充描述界線不清 | 【已驗證】左欄 tag 多為中文標籤但部分顯示英文（`ultra-detailed`、`clean sharp lines`），`#pos` 又即時翻譯並提示「這些中文還沒對應標籤」。 | 使用者不知道該點標籤還是打字，也不知道英文詞哪裡來。 | 標籤庫與 Dict 兩套資料，两组显示方式混用。 | 在 `#pos` 上方明確寫「用你自己的話描述畫面即可」，tag 改以中文為主，英文留進階。 | 不變 `sel`／`ui.extra`。 | P1 |

【已驗證】右欄「角色 LoRA」→「選擇」開 `loraModal` → 本機清單點 `toggle` 加入或用 `triggers` 開觸發詞面板 → 面板三區：我的 Trigger Words（開關、輸入、chips、不需要）、本機 metadata 建議、Civitai 版本建議（貼網址／讀取／取消）→ 生成前 `loraRemindBeforeGenerate()` `820-840` 非阻塞提醒 → `loraTokensFromSnapshot()` 注入正向字串末尾。

### 5.2 主要發現

| # | 發現 | 證據 | 困難 | 原因 | 建議 UX | 相容性影響 | 優先 |

## 8. 建議的整體資訊架構【設計建議】

維持一屏，分成三層，不新增大型彈窗：

1. **主要區（左＋中）：「我要畫什麼」**
   - 「一句話描述」：原本 `#pos`，置頂、最大輸入空間，旁邊即時顯示未對應中文提示（既有 `updateWarn`）。
   - 「挑標籤」：沿用現有分類 tab，但重整為六組貼近使用者思考：角色／外貌／服裝／動作表情／場景／畫風；品質詞從此區移除，只留右欄單一開關。
   - 「已選內容」：底列 chips 與權重；權重調整移到 hover 展開的進階控制，預設只顯示中文名。
   - 中欄維持結果舞台＋歷史條。

2. **次要區（右）：「這個角色與輸出大小」**
   - 「角色 LoRA」卡片：每張卡顯示名稱、權重、觸發詞狀態、是否自動加入；「加入角色」單一入口（合併探索/選擇的第一步）。
   - 「畫面大小／張數」維持。
   - 「畫質加成」單一開關（合併 A1）。

3. **進階區（右欄摺疊或小modal）**
   - 「不想要出現的東西」（Negative）、步數/CFG/種子、完整提示詞（L1 字串＋可選 L2 組成）、API Key、輸出資料夾、EN/成人標籤顯示。

## 9. 五條完整使用者操作流程【設計建議】

### 流程 1：從空白建立角色與畫面並生成
1. 使用者看到左欄「一句話描述」輸入框與六個標籤分類。
2. 輸入「金髮女孩站在櫻花樹下」，系統即時把可翻譯部分轉成標籤提示，未翻譯的「樹下」以小提示請補充。
3. 點「角色」分類選「女孩」，點「場景」選「櫻花」，點「畫風」選「動漫上色」。系統自動排序、去重，底列只顯示中文名。
4. 右欄點「畫質加成」（預設開）；尺寸「方形 1024」；張數 1。
5. 按「生成」。系統自動組QUALITY→標籤→描述→（無角色詞），送出並顯示進度。
6. 提示：若完全沒選、沒寫，按鈕顯示「幫我配一組標籤（你寫的描述會保留）」。

### 流程 2：選一個 LoRA、採用作者建議詞、調整後生成
1. 右欄「角色 LoRA」按「加入角色」→ 小視窗同時列出本機與探索（探索為頁籤）。
2. 選 `Amora` → 卡片出現在右欄，狀態顯示「還沒給它觸發詞」。
3. 點卡片上的「設定觸發詞」→ 觸發詞面板：上方「作者建議（選填）」顯示建議 1／建議 2，各有「加入我的詞」；下方「我的詞」可增刪。
4. 使用者按「加入建議 1」→ 那些詞出現在「我的詞」，並標「已加入」。系統**不自動加入**建議 2（服裝/姿勢）。
5. 開關「把這些詞放進這張圖」預設開；使用者可改詞、刪詞。
6. 按「生成」。系統在正向 Prompt 末尾注入個人詞；生成前若仍無詞，會指名 LoRA 提醒，不擋生成。

### 流程 3：同時使用多個 LoRA
1. 右欄已有「Amora（第 1 個角色，權重 0.80）」，再按「加入角色」選第二個 LoRA。
2. 卡片依加入順序排列，標「第 1／第 2 個角色」；各有獨立權重滑桿與觸發詞狀態。
3. 點任一卡片的「設定觸發詞」進小視窗，只影響該 LoRA；作者建議彼此不混。
4. 兩邊「我的詞」都注入正向 Prompt；系統以文字去重、保留第一次出現順序（A2 契約）。
5. 進階「完整提示詞」可看到「角色詞重複已省略」的說明，不需理解欄位。

### 流程 4：從歷史作品替換角色，保留服裝/姿勢/構圖
1. 使用者目前畫面已選好新角色（例如 Amora），點歷史縮圖開燈箱。
2. 點「把現在的角色換進這張舊圖」（原「分類套用」）→ 小視窗顯示一句話：「以這張舊圖為底，用現在的角色換掉它的角色；衣服、姿勢、構圖保留」。
3. 點「只換角色」→ 預覽兩欄：「會移除（這張圖的舊角色）」與「會帶入（現在的角色）」；通用外觀（髮色/眼睛/人數）標 ⚠ 且不預勾。
4. 使用者可取消任一預覽項目，按「套用（移除 2、加入 3）」。
5. 系統一次提交標籤，補充描述預設保留；燈箱關閉，回到主畫面。提示可看到新舊差異。

### 流程 5：從歷史還原完整設定並繼續修改
1. 燈箱點「完整還原（含角色 LoRA）」→ 小視窗摘要：「會套用這張圖的標籤、描述、負面，以及角色 LoRA（Amora 0.80）；目前的角色設定會被取代」。
2. 兩個明確按鈕：「只帶文字（保留我現在的角色）」／「完整還原（取代角色）」。
3. 選完整還原 → 系統套用 `sel/extra/neg/loras`，並提示「順序已照這張圖」。
4. 使用者直接改 `#pos` 或標籤再生成；若字典已更新，進階顯示「這張圖當時的翻譯」唯讀，不覆蓋新輸出。

## 11. 歷史重用設計【設計建議】

燈箱頂列改成三個明確動作：

1. **只帶文字**：套用標籤＋補充描述＋負向，**完全不碰 LoRA**；適合「我只是想用類似的描述」。
2. **把現在的角色換進這張舊圖**：既有分類套用，預覽兩欄＋⚠ 需確認項。
